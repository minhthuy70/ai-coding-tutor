II. TỔNG QUAN HỆ THỐNG VÀ NGUYÊN TẮC CỐT LÕI
--------------------------------------------------------------------------------
1. Mục tiêu hệ thống:
   Tự động hóa toàn diện quy trình đánh giá mã nguồn lập trình với độ tin cậy tuyệt đối, đồng thời trang bị trợ giảng ảo thông minh hỗ trợ sinh viên học tập theo phương pháp gợi mở (Socratic Method), phân tích sâu chất lượng mã, đo độ phức tạp và cảnh báo lỗ hổng bảo mật nhằm nâng cao năng lực lập trình chuẩn công nghiệp cho người học.

2. Mô hình Hai Pipeline Song Song Độc Lập (Decoupled Dual-Pipeline):
   Hệ thống duy trì kiến trúc tách biệt hoàn toàn giữa hai luồng xử lý:

   [PIPELINE 1: LUỒNG CHẤM ĐIỂM CHÍNH THỨC - OFFICIAL GRADING PIPELINE]
   Student Code ---> Submission Queue (Redis) ---> Docker Sandbox Worker
                                                      |
                                                      +--> Compile / Runtime Cô Lập
                                                      +--> Chạy Test Cases (Public + Hidden)
                                                      +--> Đo lường CPU, RAM, Execution Time
                                                      |
                                                      v
                                          AUTO-GRADER SCORING ENGINE
                                                      |
                                                      v
                                          KẾT QUẢ ĐIỂM CHÍNH THỨC (Official Score)
                                          (Phán quyết chuẩn: AC, WA, TLE, MLE, CE, RE)

   [PIPELINE 2: LUỒNG TRỢ GIẢNG & PHÂN TÍCH AI MỞ RỘNG (AI TUTOR & RAG PIPELINE)]
   Dữ liệu tổng hợp (Evidence):
   - Yêu cầu bài toán (Problem Description, Constraints)
   - Mã nguồn của sinh viên (Student Code)
   - Bằng chứng thực thi (Execution Evidence: Compiler Error, Failed Test Case Type, Resource Metrics)
   - Phân tích tĩnh (Static Analysis: AST Parser, Flake8 PEP8, Radon Cyclomatic Complexity)
   - Kho Tri thức RAG (ChromaDB: DSA Guidelines, Error Patterns, Secure Coding CWE/OWASP)
                                                      |
                                                      v
                                            CONTEXT BUILDER
                                                      |
                                                      v
                                      LANGCHAIN PROMPT & GUARDRAILS
                                                      |
                                                      v
                             MULTI-PROVIDER LLM ENGINE (Gemini Flash / OpenAI / Ollama Local)
                                                      |
                                                      v
                                        STRUCTURED OUTPUT (Pydantic)
                                        - Gợi ý tư duy Socratic (Hint / Explanation)
                                        - Phân tích độ phức tạp Big-O & Cyclomatic (Complexity)
                                        - Chấm điểm Clean Code & Code Smells (Quality Score)
                                        - Cảnh báo Lỗ hổng Bảo mật (Security Vulnerabilities)

3. Nguyên tắc vận hành nền tảng:
   - Nguyên tắc 1: Auto-Grader là nguồn chân lý duy nhất (Single Source of Truth) quyết định điểm số chính thức và trạng thái nộp bài của sinh viên.
   - Nguyên tắc 2: AI đóng vai trò phân tích, hỗ trợ và giải thích sư phạm, tuyệt đối KHÔNG có quyền can thiệp hay làm thay đổi điểm số học thuật chính thức.
   - Nguyên tắc 3: Tính độc lập và chịu lỗi (Fault-Tolerance) cao. Nếu dịch vụ AI gặp sự cố (hết quota, timeout, mất mạng ngoài), luồng chấm bài của Auto-Grader vẫn hoạt động trơn tru 100%, sinh viên vẫn nhận đầy đủ kết quả điểm số và phán quyết bài nộp.

--------------------------------------------------------------------------------
III. KIẾN TRÚC VÀ CÁC THÀNH PHẦN AI NÂNG CẤP
--------------------------------------------------------------------------------
1. Định vị kiến trúc AI:
   - Nhóm áp dụng kiến trúc Hybrid AI Tutor kết hợp Evidence-Grounded AI và Retrieval-Augmented Generation (RAG).
   - Tận dụng sức mạnh suy luận của LLMs tiên tiến kết hợp với bằng chứng thực thi thực tế từ Sandbox và tài liệu chuẩn từ Vector DB để loại bỏ hoàn toàn hiện tượng ảo giác (hallucination).

2. Hệ sinh thái Đa Mô hình (Multi-Provider AI Engine):
   - Engine chính (Primary): Google Gemini 1.5 / 2.0 Flash API (tốc độ < 2s, Free Tier vĩnh viễn 1.500 lượt/ngày, cửa sổ ngữ cảnh 1M tokens).
   - Engine dự phòng Cloud (Fallback): OpenAI GPT-4o-mini API (kích hoạt khi Gemini quá tải).
   - Engine mã nguồn mở Cục bộ (Local LLM Support qua Ollama): Hỗ trợ tích hợp Llama 3.1 (8B) hoặc Mistral (7B) chạy offline trong container nội bộ, đáp ứng nhu cầu bảo mật dữ liệu tuyệt đối và không phụ thuộc internet.

3. Khung điều phối LangChain & Context Engineering (ContextBuilder):
   - Sử dụng LangChain để chuẩn hóa các chuỗi Prompt (Prompt Chains) và Output Parsers.
   - ContextBuilder gom ngữ cảnh toàn diện:
     + Đề bài & ràng buộc thời gian/bộ nhớ.
     + Mã nguồn sinh viên nộp.
     + Bằng chứng thực thi từ Sandbox (loại bỏ hoàn toàn input/output của test case ẩn).
     + Kết quả phân tích tĩnh AST / Flake8 / Radon.
     + Tri thức liên quan truy xuất từ ChromaDB RAG.

4. Module Phân tích Lỗ hổng Bảo mật (AI-based Security Vulnerability Analysis):
   - Phân tích mã nguồn sinh viên theo chuẩn OWASP và CWE Top 25:
     + Phát hiện rủi ro SQL Injection / Command Injection (với mã có thao tác query/command).
     + Phát hiện nguy cơ Tràn bộ đệm (Buffer Overflow / Out-of-bounds Array Access đối với C/C++).
     + Phát hiện thông tin đăng nhập/mật khẩu gán cứng (Hardcoded Credentials/Secrets).
     + Phát hiện hàm sinh số ngẫu nhiên không an toàn (Insecure Randomness) hoặc thao tác file nguy hiểm.
   - Kết quả trả về cấu trúc rõ ràng: Tên lỗ hổng, mức độ nghiêm trọng (Low/Med/High/Critical), vị trí dòng code và hướng dẫn khắc phục an toàn.

5. Kho Tri thức RAG Chuyên sâu (ChromaDB Knowledge Taxonomy):
   - Lưu trữ khoảng 350 - 500 tài liệu tuyển chọn (~5.000 - 8.000 chunks vector, dung lượng nhẹ 150MB - 300MB):
     + Python: PEP 8, AST Idioms, 300+ Error Patterns.
     + C++: STL, Pointer & Memory Management, 250+ Error Patterns.
     + Java & JavaScript: OOP Best Practices, Exception Handling, 200+ Error Patterns.
     + Mảng dùng chung: Cấu trúc Dữ liệu & Giải thuật (DSA), Quy chuẩn Clean Code & Code Smells, Phân tích Big-O, và Danh mục CWE An toàn lập trình.

6. Phương pháp Socratic Method & Guardrails Bảo vệ:
   - System Prompt dẫn dắt tư duy: Gợi ý thuật toán, đặt câu hỏi phản biện, phân tích nguyên nhân lỗi logic, TUYỆT ĐỐI không sinh mã nguồn hoàn chỉnh thay cho sinh viên.
   - Chống Prompt Injection: Bao bọc dữ liệu sinh viên trong thẻ định danh cách ly an toàn, ngăn chặn hoàn toàn các câu lệnh ép AI đưa ra đáp án.
   - Định dạng đầu ra có cấu trúc (Structured Output): Sử dụng Pydantic Schema ép buộc JSON xác thực (quality_score, complexity_score, cyclomatic_analysis, code_smells, security_vulnerabilities, socratic_hints).
