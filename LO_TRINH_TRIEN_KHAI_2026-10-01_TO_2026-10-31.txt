I. TỔNG QUAN DỰ ÁN
----------------------------------------------------------------------------------------------------

1. Mục tiêu cốt lõi:
Xây dựng một nền tảng chấm bài lập trình tự động (Auto-Grader) an toàn tuyệt đối bằng Docker Sandbox,
kết hợp hệ thống Trợ giảng Ảo (AI Coding Tutor) sư phạm theo phương pháp Socratic. Hệ thống không
chỉ so khớp kết quả đúng/sai (Deterministic evaluation) mà còn phân tích tĩnh mã nguồn (Static analysis)
và đưa ra gợi ý, câu hỏi định hướng tư duy (Context-aware semantic feedback) giúp sinh viên tự sửa lỗi,
tuyệt đối không giải hộ toàn bộ bài làm.

2. Phạm vi 48 Use Cases chia thành 5 nhóm Actor:
- Sinh viên (10 UC: UC-07 → UC-16): Xem bài, viết code Monaco, upload file, nộp bài, xem kết quả sandbox,
  xem nhận xét AI, tương tác AI Tutor Socratic, xem lịch sử làm bài, xem bảng điểm cá nhân.
- Giáo viên (15 UC: UC-17 → UC-31): Quản lý lớp, quản lý/cấu hình bài tập, deadline, test case, rubric,
  giao bài cho lớp, xem bài nộp, xem điểm, xem AI đánh giá, chấm bài thủ công theo Rubric (override score).
- Quản trị viên (6 UC: UC-32 → UC-37): Quản lý tài khoản (tạo, khóa/mở, xóa mềm), phân quyền, reset mật khẩu,
  import danh sách người dùng từ Excel/CSV chuẩn 5 cột.
- Quản lý lớp cấp cao (Quản trị viên & Giáo vụ) (6 UC: UC-38 → UC-43): Tạo/sửa lớp theo phạm vi, đóng/mở lớp,
  quản lý vòng đời lưu trữ & xóa lớp (Hard-delete guard: SV=0 && Bài=0 && Lịch=0; Archive/Restore -> Đã đóng),
  quản lý sinh viên trong lớp, phân công Giáo viên vào lớp theo Khoa/Bộ môn.
- Quản trị viên hệ thống (5 UC: UC-44 → UC-48): Cấu hình tham số AI (API Key, model, temperature), cấu hình
  Docker Sandbox, giám sát Docker Sandbox (dừng execution -> cập nhật bài nộp sang "Bị gián đoạn", không tăng
  submission_count, không auto-regrade), quản lý tổ chức / Khoa / Bộ môn / gán Giáo vụ (UC-47), quản lý System Logs
  và audit trail mọi lượt submit (UC-48).
- Nhóm dùng chung (6 UC: UC-01 → UC-06): Đăng nhập, Đăng xuất, Quên mật khẩu, Xem thông tin cá nhân,
  Cập nhật thông tin cá nhân, Đổi mật khẩu.

3. 4 Trụ cột MVP Core (Bắt buộc chạy hoàn chỉnh):
1. Quản lý bài tập (Problem Management & Test Cases)
2. Web IDE & Nộp bài (Monaco Editor & Submission Queue)
3. Chấm tự động cách ly (Docker Sandbox Auto-Grader)
4. Trợ giảng AI sư phạm (Context-Aware Socratic AI Tutor)

4. Nguyên tắc triển khai thực tế (Production-Mindset):
- Không "học công nghệ" trên lịch làm việc: Mỗi ngày đều có Output, Deliverable và Test cụ thể.
- Tích hợp sớm (Continuous Integration): Ghép nối Frontend <-> Backend <-> Sandbox <-> AI từng chặng.
- Auto-Grader thực tế: Chạy code sinh viên trong container thật, đo CPU/RAM, ngắt mạng, bắt TLE/MLE/RE/CE/AC/WA.
- AI Tutor có bằng chứng: Input cho AI phải có Code + Đề bài + Execution Evidence + Rubric.
- Đảm bảo Data Integrity: Không ghi đè bài nộp cũ, mỗi lần Submit hợp lệ là một bản ghi độc lập.

VI. TECH STACK CHÍNH THỨC
----------------------------------------------------------------------------------------------------

Backend:
- Ngôn ngữ: Python 3.11 (Asynchronous)
- Web Framework: FastAPI (Hiệu năng cao, OpenAPI tự động, native async/await)
- Database: PostgreSQL 15 (Lưu trữ quan hệ toàn vẹn, JSONB cho test results)
- ORM & Migrations: SQLAlchemy 2.0 (Async engine) + Alembic
- In-memory Broker / Cache: Redis 7
- Asynchronous Task Queue: Celery 5.3
- Authentication: PyJWT (Access token 15m, Refresh token 7d), Passlib (bcrypt)
- Real-time: Native FastAPI WebSockets

Frontend:
- Framework: Next.js 14 (React 18, App Router, Server & Client Components)
- Styling: Tailwind CSS (Không dùng Tailwind v4 unstable, dùng v3.4 chuẩn ổn định)
- Code Editor: Monaco Editor (@monaco-editor/react) - Trình soạn thảo cốt lõi của VS Code
- Markdown & Math: react-markdown + remark-math + rehype-katex (Hỗ trợ công thức LaTeX)
- State Management: Zustand (Lightweight, linh hoạt hơn Redux)
- Real-time Client: Native WebSocket API / ReconnectingWebSocket
- HTTP Client: Axios (Interceptors xử lý refresh token tự động)

Sandbox & Isolation:
- Container Engine: Docker Engine 24.x
- Sandbox Isolation: Non-root container user (`uid: 1001`), gVisor (`runsc`) / drop capabilities
- Security Constraints: `--network none`, `--memory 256m`, `--cpus 1.0`, `--pids-limit 64`, `--read-only`
- Execution Runner: Python runner script thu thập stdout, stderr, execution time, memory usage, exit code

AI & Static Analysis:
- Primary AI Engine: Google Gemini API (gemini-1.5-flash: tốc độ nhanh, chi phí tối ưu, free tier hào phóng)
- Fallback AI Engine: OpenAI API (gpt-4o-mini)
- Local AI (Dự phòng offline): Ollama (codellama:7b / deepseek-coder:6.7b)
- Static Code Analysis: Python `ast` module, `radon` (Cyclomatic Complexity, Maintainability Index), `flake8`

DevOps & Testing:
- Reverse Proxy: Nginx (Production gateway, SSL termination, WebSocket reverse proxy)
- CI/CD: GitHub Actions (Linter, Unit tests, Docker build)
- Testing Frameworks: Pytest (Backend unit/integration), Locust (Load testing), Playwright (E2E UI testing)


VII. DATABASE SCHEMA SUMMARY (CHUẨN HÓA THEO DOAN4.MD & RULES.MD)
----------------------------------------------------------------------------------------------------

1. `organizations`:
   - id (UUID, PK), name (VARCHAR), code (VARCHAR, UNIQUE), is_active (BOOLEAN), created_at (TIMESTAMP).
2. `departments`:
   - id (UUID, PK), organization_id (UUID, FK), name (VARCHAR), code (VARCHAR, UNIQUE), created_at (TIMESTAMP).
3. `users`:
   - id (UUID, PK), organization_id (UUID, FK), department_id (UUID, FK, NULLABLE), email (VARCHAR, UNIQUE),
   - hashed_password (VARCHAR), full_name (VARCHAR), role (ENUM: STUDENT, TEACHER, STAFF, ADMIN, SUPER_ADMIN),
   - is_active (BOOLEAN), is_temporary_password (BOOLEAN), created_at (TIMESTAMP), deleted_at (TIMESTAMP, NULLABLE).
4. `classes`:
   - id (UUID, PK), organization_id (UUID, FK), department_id (UUID, FK), teacher_id (UUID, FK, NULLABLE),
   - name (VARCHAR), code (VARCHAR, UNIQUE), description (TEXT),
   - status (ENUM: ACTIVE, CLOSED, ARCHIVED - mặc định ACTIVE), created_at (TIMESTAMP).
5. `class_members`:
   - id (UUID, PK), class_id (UUID, FK), user_id (UUID, FK), joined_at (TIMESTAMP), UNIQUE(class_id, user_id).
6. `problems`:
   - id (UUID, PK), author_id (UUID, FK), title (VARCHAR), description (TEXT - Markdown/LaTeX),
   - allowed_languages (VARCHAR[]), difficulty (ENUM: EASY, MEDIUM, HARD),
   - time_limit_sec (FLOAT), memory_limit_mb (INT), is_active (BOOLEAN), created_at (TIMESTAMP).
7. `test_cases`:
   - id (UUID, PK), problem_id (UUID, FK), input_data (TEXT), expected_output (TEXT),
   - is_sample (BOOLEAN - công khai cho SV), score_weight (FLOAT), order_index (INT).
8. `rubric_criteria`:
   - id (UUID, PK), problem_id (UUID, FK), criteria_name (VARCHAR), description (TEXT),
   - max_score (FLOAT), weight_percentage (FLOAT). (Bao gồm tiêu chí tự động 'Correctness').
9. `class_assignments`:
   - id (UUID, PK), class_id (UUID, FK), problem_id (UUID, FK), deadline (TIMESTAMP),
   - allow_late_submission (BOOLEAN), late_deadline (TIMESTAMP, NULLABLE), late_penalty_percent (FLOAT),
   - max_submissions (INT - 0 là unlimited), scoring_policy (ENUM: HIGHEST_SCORE, LATEST_SCORE),
   - is_active (BOOLEAN), created_at (TIMESTAMP).
10. `submissions`:
    - id (UUID, PK), user_id (UUID, FK), problem_id (UUID, FK), class_id (UUID, FK, NULLABLE),
    - assignment_id (UUID, FK, NULLABLE), source_code (TEXT), language (ENUM: PYTHON, CPP, JAVA),
    - status (ENUM: PENDING, RUNNING, COMPLETED, INTERRUPTED),
    - auto_score (FLOAT, NULLABLE), manual_score (FLOAT, NULLABLE), final_score (FLOAT, NULLABLE),
    - is_manual_graded (BOOLEAN), execution_time_sec (FLOAT), memory_used_kb (INT),
    - is_late (BOOLEAN), late_penalty_applied (FLOAT), submitted_at (TIMESTAMP).
11. `test_results`:
    - id (UUID, PK), submission_id (UUID, FK), test_case_id (UUID, FK),
    - status (ENUM: AC, WA, TLE, MLE, RE, CE), actual_output (TEXT), error_message (TEXT),
    - execution_time_sec (FLOAT), memory_used_kb (INT), score_awarded (FLOAT).
12. `ai_feedback`:
    - id (UUID, PK), submission_id (UUID, FK), quality_score (FLOAT), complexity_score (FLOAT),
    - static_analysis_metrics (JSONB), logic_analysis (TEXT), pedagogical_hints (TEXT),
    - raw_response (TEXT), created_at (TIMESTAMP).
13. `tutor_conversations`:
    - id (UUID, PK), submission_id (UUID, FK), user_id (UUID, FK),
    - role (ENUM: USER, ASSISTANT), message (TEXT), created_at (TIMESTAMP).
14. `manual_grades`:
    - id (UUID, PK), submission_id (UUID, FK), grader_id (UUID, FK),
    - rubric_scores (JSONB), total_score (FLOAT), feedback_comment (TEXT),
    - is_draft (BOOLEAN - True là lưu tạm, False là chính thức), updated_at (TIMESTAMP).
15. `system_logs` (Audit Log):
    - id (UUID, PK), user_id (UUID, FK, NULLABLE), action (VARCHAR), event_type (VARCHAR),
    - resource_type (VARCHAR), resource_id (VARCHAR), details (JSONB),
    - ip_address (VARCHAR), created_at (TIMESTAMP).

  6. `disk_filler.py`: Ghi file rác 10GB -> Xác nhận `--read-only` rootfs chặn việc ghi đĩa bừa bãi.

X. QUẢN TRỊ RỦI RO & PHƯƠNG ÁN GIẢM THIỂU (RISK MANAGEMENT)
----------------------------------------------------------------------------------------------------

RỦI RO 1: Mã nguồn sinh viên gây sập máy chủ (Infinite loop, Memory leak, Fork bomb)
- Xác suất: Cao | Mức độ ảnh hưởng: Nghiêm trọng
- Biện pháp xử lý: Sử dụng cơ chế cách ly tuyệt đối của Docker:
  + Giới hạn tài nguyên ở cấp Kernel cgroups: `--cpus=1.0`, `--memory=256m`, `--pids-limit=64`.
  + Script runner độc lập áp dụng `subprocess.run(timeout=limit)` và bắt tín hiệu SIGKILL.
  + Ngắt toàn bộ mạng bằng cờ `--network none`. Chạy dưới tài khoản không đặc quyền `nobody`/`non-root`.

RỦI RO 2: AI API gặp sự cố (Rate limit, Latency cao, Mất kết nối, Chi phí)
- Xác suất: Trung bình | Mức độ ảnh hưởng: Đáng kể
- Biện pháp xử lý:
  + Cấu hình cơ chế Fallback tự động: Google Gemini 1.5 Flash -> OpenAI GPT-4o-mini -> Ollama Local model.
  + Cơ chế Cache AI Feedback: Nếu sinh viên nộp lại mã nguồn giống hệt hoặc cùng mã lỗi, sử dụng cache.
  + Xử lý bất đồng bộ: AI Feedback được sinh ngầm sau khi có kết quả Sandbox, không làm nghẽn tiến trình chấm điểm.

RỦI RO 3: Quá tải hàng đợi khi nhiều sinh viên nộp bài cùng thời điểm
- Xác suất: Trung bình | Mức độ ảnh hưởng: Trung bình
- Biện pháp xử lý:
  + Sử dụng kiến trúc Producer-Consumer với Celery và Redis Broker.
  + Giới hạn số lượng worker container đồng thời (ví dụ 4 - 8 workers) để không cạn kiệt CPU máy chủ.
  + Trả về `submission_id` ngay lập tức (HTTP 202 Accepted) và cập nhật tiến độ qua WebSockets.

RỦI RO 4: Sai sót phân quyền đa cấp giữa 5 vai trò (RBAC Scope Leakage)
- Xác suất: Trung bình | Mức độ ảnh hưởng: Cao
- Biện pháp xử lý:
  + Thiết kế Middleware Scope Enforcement độc lập: Mọi request đều kiểm tra Role + Department/Class Scope.
  + Giáo viên chỉ được truy cập lớp mình làm chủ nhiệm; Giáo vụ chỉ quản lý lớp thuộc Khoa mình.
  + Viết bộ 30 Unit Tests chuyên biệt cho ma trận phân quyền (Class Actor Matrix - RULES §21).

RỦI RO 5: Gián đoạn phiên chấm hoặc máy chủ khởi động lại bất ngờ
- Xác suất: Thấp | Mức độ ảnh hưởng: Trung bình
- Biện pháp xử lý:
  + Tuân thủ nghiêm ngặt RULES §15 & §16: Bài nộp bị treo chuyển sang trạng thái "Bị gián đoạn".
  + Tuyệt đối KHÔNG tự động re-grade vô hạn, KHÔNG tăng biến đếm `submission_count`.
  + Thông báo sinh viên nộp lại và ghi sự kiện vào System Logs.
