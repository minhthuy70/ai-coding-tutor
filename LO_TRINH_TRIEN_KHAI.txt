I. TỔNG QUAN DỰ ÁN
------------------------------------------------------------------------------------------------------------------------------------------------

Mục tiêu: Xây dựng nền tảng chấm bài lập trình tự động có tích hợp AI tutor để đánh giá code và
cung cấp phản hồi sư phạm cho sinh viên.

Scope: 44 Use Cases (chuẩn hóa DOAN4.md) chia thành 5 nhóm Actor:
- Sinh viên (10 UC): Làm bài, nộp bài, xem kết quả, tương tác AI Tutor
- Giáo viên (11 UC): Quản lý bài tập, chấm điểm thủ công, đóng/mở lớp phụ trách, bài tập, chấm điểm thủ công
- Quản trị viên (7 UC): Quản lý tài khoản, lớp học cấp trường
- Giáo vụ (6 UC): Quản lý lớp học cấp Khoa/Bộ môn
- Quản trị viên hệ thống (4 UC): Cấu hình AI, Docker Sandbox, System Logs

4 Trụ cột MVP Core:
1. Quản lý bài tập (Problem Management)
2. Web IDE & Nộp bài (Monaco Editor)
3. Chấm tự động (Docker Sandbox Auto-Grader)
4. Trợ giảng AI (AI Tutor & Code Reviewer)

VI. TECH STACK
------------------------------------------------------------------------------------------------------------------------------------------------

Backend:
- Language: Python 3.11
- Framework: FastAPI
- Database: PostgreSQL 15
- Queue: Redis 7
- Task Queue: Celery
- ORM: SQLAlchemy
- Auth: JWT (PyJWT)
- Password: bcrypt

Frontend:
- Framework: Next.js 14 (App Router)
- Styling: Tailwind CSS
- Editor: Monaco Editor
- State: React Context/Zustand
- Real-time: WebSocket (Socket.io)
- HTTP: Axios/Fetch

Infrastructure:
- Container: Docker 24
- Sandbox: gVisor/non-root container
- Reverse Proxy: Nginx (production)
- CI/CD: GitHub Actions

AI:
- Primary: Google Gemini API
- Fallback: OpenAI GPT-4o
- Local: Ollama (optional)


VII. DATABASE SCHEMA SUMMARY
------------------------------------------------------------------------------------------------------------------------------------------------

Core Tables:
- users: id, email, hashed_password, full_name, role, organization_id, is_active
- organizations: id, name, code
- departments: id, name, code, organization_id
- classes: id, name, code, status, organization_id, department_id, teacher_id
- class_members: id, class_id, user_id, role
- problems: id, title, description, allowed_languages, time_limit, memory_limit, author_id
- test_cases: id, problem_id, input_data, expected_output, is_sample, score_weight
- rubric_criteria: id, problem_id, criteria, description, max_score, weight
- class_assignments: id, class_id, problem_id, deadline, is_active
- submissions: id, user_id, problem_id, class_id, source_code, language, status
- test_results: id, submission_id, test_case_id, status, execution_time, memory_used
- ai_feedback: id, submission_id, quality_score, complexity_score, logic_analysis, hints
- manual_grades: id, submission_id, grader_id, score, comments

X. RISK MITIGATION
------------------------------------------------------------------------------------------------------------------------------------------------

Risk 1: Docker Sandbox security
- Mitigation: Use gVisor, non-root user, network isolation, resource limits

Risk 2: AI API cost/latency
- Mitigation: Cache feedback, batch processing, fallback to local model

Risk 3: Deadline pressure (8 weeks → 4 weeks compressed)
- Mitigation: Cut P1/P2 features, focus on P0 only, reduce test coverage

Risk 4: 2-person team bandwidth
- Mitigation: Parallel work, clear separation, daily sync, code review

Risk 5: Complex RBAC implementation
- Mitigation: Use middleware pattern, document scope rules clearly
